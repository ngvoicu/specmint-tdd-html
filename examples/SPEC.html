Overview

Build a per-IP token-bucket rate-limit middleware for the Express API. Each request consumes a token; tokens refill at a configurable rate. When the bucket is empty, the middleware responds with 429 Too Many Requests and a Retry-After header. Strict TDD: every behavior begins as a failing test, then the minimum implementation to pass, then refactor under green.

Acceptance Criteria

0/0
  • Token bucket refills at the configured rate; never exceeds the configured capacity.
  • Consuming a token decrements the bucket; consuming an empty bucket returns false without going negative.
  • Express middleware wires the bucket per-request and reads the client IP correctly behind a proxy.
  • Each unique IP gets its own bucket; buckets persist across requests within a single process.
  • A 429 response includes a Retry-After header (seconds) and X-RateLimit-* headers.
  • Every behavior above has a corresponding red-green-refactor cycle recorded in the TDD Log.

Anti-Patterns to Avoid

  • No real timers in unit tests — use fake-timers for refill behavior
  • No mocking the bucket internals — test by behavior, not by implementation
  • No sleep-based waits in integration tests — advance time deterministically
  • No SQLite or other stand-ins for the in-process Map — keep the store interface narrow and test it directly
